# Versioning and compatibility

What a version number of `TcgDex.CSharpSdk` promises. This page is the contract; the reasoning behind each
rule is in [DECISIONS](DECISIONS.md) (#36 and #39).

The package follows [Semantic Versioning 2.0](https://semver.org/spec/v2.0.0.html). Before `1.0.0` the
minor number carries breaking changes (0.8.0 and 0.9.0 did), and the
[changelog](https://github.com/PinKushin/TcgDex.CSharpSdk/blob/main/CHANGELOG.md) says so under each one.
From `1.0.0` the rules below hold.

## What counts as the public API

Everything in the pinned surface,
[`PublicApi.approved.cs`](https://github.com/PinKushin/TcgDex.CSharpSdk/blob/main/TcgDex.CSharpSdk.Tests/PublicApi.approved.cs).
A change to it fails a test, so it cannot happen by accident. Anything `internal`, and anything in a
namespace that is not in that file, is not public API and can change in any release.

## What each number means

| Release | May contain | Never contains |
|---|---|---|
| **Patch** (`1.0.1`) | Bug fixes, documentation, dependency updates that change no behaviour | New public members, behaviour a caller could reasonably depend on changing |
| **Minor** (`1.1.0`) | New public types and members, new optional parameters on methods that are not on an interface, new properties on `CardFilter`, `CardQuery`, `TcgDexOptions` and the models, `[Obsolete]` markings, dropping an end-of-life target framework (below) | Removing or renaming a public member, changing a signature, changing what a call returns for the same input |
| **Major** (`2.0.0`) | Anything above, plus removals and signature changes | |

A model gaining a property because the TCGdex API gained a field is a minor release. A value the API
newly returns in an existing field (a new rarity, a new category) is not a change to the SDK at all:
those fields are text, not enums, for exactly this reason.

## Interfaces

`ITcgDexClient`, `ICardResource`, `ICardSetResource`, `ISeriesResource`, `ICatalogResource` and
`IRandomResource` exist so that you can inject and fake the client in your tests. They are for
**consuming**. A minor release may add a member to one of them, so a class of your own that
implements one by hand can stop compiling on an upgrade. A mock or a substitute generated by a mocking
library keeps working.

`ITcgDexResponseCache` is the exception. It is a deliberate extension point (Redis, disk), and it will
**not** gain members within a major version.

To keep that growth small, new options go on the sealed types the interfaces take
(`CardFilter`, `CardQuery`), not onto method signatures.

## Target frameworks

The package ships `net10.0`, `net8.0` and `netstandard2.0`. NuGet picks the closest match, and
`netstandard2.0` serves .NET Framework and the .NET versions between; [getting started](getting-started.md)
lists which framework gets which asset.

A target framework may be **dropped in a minor release once its runtime is out of support**. That is
safe because a consumer on the dropped framework falls back to the `netstandard2.0` asset: the API is the
same, nothing stops compiling, and only the framework-specific tuning is lost. The changelog names the
drop. `net8.0` leaves support on 2026-11-10, so it is the first candidate.

A target framework is never dropped while its runtime is supported.

## Deprecation

A public member is marked `[Obsolete]` in a minor release, with a message naming the replacement, and is
removed no earlier than the next major release. There is no promise about how many minor releases lie
between the two, only that the mark comes first.

## Which versions get fixes

Only the latest release of the current major version. This is a single-maintainer project, and holding
a second line open would mean fixes arriving late on both. A security report is handled as
[`SECURITY.md`](https://github.com/PinKushin/TcgDex.CSharpSdk/blob/main/SECURITY.md) describes, and
the fix ships as a patch release of the latest version.

## What is not promised

- **The TCGdex service itself.** This SDK reads a third-party API. It can change a field or add a
  rate limit without notice, and the SDK follows it; see [api-info](api-info.md) for what has been
  observed.
- **The wire requests** are not API: a release may send a different, equivalent request, for example a
  different page size. The changelog records a change a caller can observe.
- **Exact log text and exception messages.** Log categories, `TcgDexApiException.Kind` and the exception
  types are API; the wording is not.
